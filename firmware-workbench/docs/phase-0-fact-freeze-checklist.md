## 3. 确定性构建 Spike

需要在一台干净开发机或干净容器中执行三次构建：

1. 固定 SDK、工具链、依赖源和环境变量。
2. 输出 bootloader、kernel、DTB、rootfs、应用包和最终刷机包的 SHA-256。
3. 记录命令、耗时、CPU/内存/磁盘需求和所有下载项。
4. 第二、三次构建不得依赖第一次未声明的缓存。
5. 若字节级不可重复，必须列出可解释差异，并对可部署内容做语义一致性检查。

门禁输出：`platform-pack.yml`、锁定的容器镜像 digest、`build-manifest.json`、产物哈希和已知非确定性清单。

## 4. 面板 UI 与 VNC Spike

必须确认：

- UI 技术栈：X11、Wayland、Qt eglfs/linuxfb、Web 或厂商私有 compositor。
- 分辨率、旋转、色深、触控输入设备、坐标变换和多点触控需求。
- 候选 Provider：x11vnc、wayvnc、Qt VNC/eglfs 方案或只读截图 + 独立输入注入。
- VNC 服务是否只绑定设备管理网，是否需要 SSH 隧道，认证信息不得写入仓库。

通过条件：连续连接 30 分钟；重启后可恢复；画面方向与触控坐标一致；能完成一次本地复印交互；CPU/内存开销已记录；串口和 VNC 能被同一时间线关联。

## 5. 设备连接、刷机与救援

| 接口 | 当前值 | Spike | 通过条件 |
|---|---|---|---|
| Windows 串口 COM、波特率、登录方式 | 待填写 | 接入现有 `dsh-linux-monitor` | 单一控制器共享 UI/模型，断线自动恢复 |
| SSH 地址、用户、认证方式 | 待填写 | 固定只读健康检查与部署目录 | 不把密码/私钥写入仓库和 SQLite |
| 正常部署方式 | 待填写 | 上传、校验、原子切换、服务重启 | 失败可回退且保留旧版本 |
| 全量刷机方式 | 待填写 | 厂商工具/USB/SD/网络 | 能记录镜像、设备身份、操作者和结果 |
| 救援入口 | 待填写 | MaskROM、recovery、备用介质或串口 U-Boot | 故意刷入坏应用后能恢复 |
| 可控断电 | 待填写 | 继电器型号、控制协议、安全限制 | 可在指定阶段断电并可靠重新上电 |

## 6. 扫描模块接口

冻结以下契约：物理总线、控制协议、数据通道、像素格式、分辨率、行宽/stride、颜色顺序、曝光与校准、起停时序、超时、原稿检测、ADF 状态、错误码和复位方法。

Spike 至少采集：正常 A4 页面、空白页、黑白边界图、校准失败、原稿中断和超时。每个样本必须有原始数据、协议时间线和预期判定，以便建设虚拟扫描器与黄金样张测试。

## 7. 打印引擎接口

冻结以下契约：物理总线、命令/响应、作业生命周期、页面数据格式、缓冲与流控、预热/就绪、纸盒与纸张、耗材、门盖、卡纸位置、温度、安全停机、取消、复位和所有故障码。

Spike 至少覆盖：空闲到就绪、单页输出、连续页、缺纸、门盖打开、可恢复卡纸、不可恢复故障、作业取消和通信中断。输出协议录制文件和可用于虚拟引擎的状态机。

## 8. Dagu Runner Spike

使用独立 Adapter 验证以下最小工作流，不让领域模型直接依赖 Dagu 文件格式：

1. 两个无依赖构建任务并行。
2. 一个单项测试等待其开发任务完成。
3. 一个设备任务因 Printer-01 被占用而排队。
4. 基础设施失败按策略重试一次，产品失败不自动重试。
5. 人工验收任务暂停并等待签核。
6. 取消任务后，子进程、资源租约和临时文件均被清理。
7. Dagu 重启后能恢复状态，SQLite 仍是工作台事实索引。

输出决策：采用 Dagu、延后采用，或替换 Runner；无论选择哪一种，必须保留 `RunnerAdapter` 边界。

## 9. Phase 0 退出门禁

只有以下条件全部满足，才能进入真实样机 Provider 和 RK3588 Platform Pack 实现：

- P0 产品基线和验收阈值已由产品负责人签署。
- BSP、构建命令、产物、刷机和救援路径已在目标样机验证。
- UI 技术栈和 VNC Provider 已通过 Spike。
- 扫描器、引擎最小协议契约和录制样本已归档。
- 设备、串口、VNC、扫描器、引擎、断电夹具和人工位的资源策略已确认。
- 安全边界、凭据存放、危险操作确认和审计要求已确认。
- Dagu Runner 决策已有可复现实验结果。
- 详细设计评审确认下一阶段不会依赖未冻结的关键事实。
